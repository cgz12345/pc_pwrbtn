# pc_pwrbtn — ESP32-S3 电脑远程开关机 / 复位 / 状态回读

一块 ESP32-S3 并接在机箱的电源键、复位键上，用 **MQTT** 远程控制电脑，并能读回**电脑真实的开关机状态**和硬盘活动。

**设计原则：烧进去就能用。** WiFi / MQTT / 引脚全部来自 `secrets.h`（编译期），
不需要网页、不需要配网热点；要改参数用**手机蓝牙 App**写一段 JSON 即可（也可以改 `secrets.h` 重烧）。

```
手机 MQTT App ─→ MQTT broker ─→ ESP32-S3 ─┬─→ PWR_SW    短按 / 长按(=硬断电)
手机蓝牙 App  ────────────────────────────┤
串口           ────────────────────────────┴─→ RESET_SW  按一下(=硬重启)
                                            └─← 电源灯 / SATA 5V / 硬盘灯（读状态）
```


## ⚠️ 危险性与安全警告 (Security & Risk Notice)

在部署和公开使用本项目前，请**务必仔细阅读**以下安全与硬件风险说明：

1. **公网 MQTT Broker 劫持风险 (最核心安全隐患)**
   - 默认使用的 `broker.emqx.io:8883` 是免密公共 MQTT 服务器。
   - **主题名 (Topic) 本身就是唯一的开机与关机密码！**
   - 任何人在任何地点只要得知了你的完整 Topic（例如通过未脱敏的代码、截图或代码仓库），即可直接向你的电脑发送 `press`（正常开关机）或 `force`（强制切断电源）指令。
   - **防护要求**：公开代码时必须将 `MQTT_TOPIC_BASE` 替换为随机占位符；在自己实际烧录时，必须配置一段足够长、包含随机字符且其他人绝对猜不到的专属前缀（如 `pcbtn/a8f9c1e7d24b60`），或自建带账号密码鉴权的私有 MQTT Broker。

2. **强制断电 (Force Shutdown / Hold 6s) 的数据风险**
   - 固件支持长按电源键 6 秒模拟硬件硬断电（等同于直接拔掉机箱电源线）。
   - **危险**：在操作系统正在运行或磁盘高负载读写时触发强制断电，将导致未保存的数据丢失、数据库损坏甚至操作系统引导异常。
   - **防护要求**：该命令仅限电脑彻底死机、远程桌面与网络完全失去响应时的最后兜底手段。前端 Web App 已内置二次确认防误触弹窗。

3. **硬件与引脚安全 (严禁高压倒灌)**
   - ESP32-S3 的 GPIO 工作电平为 **3.3V**（绝对最大耐受极限为 3.6V），**芯片不支持 5V/12V 电平输入！**
   - **控制引脚 (GPIO 5 / GPIO 6)** 必须且只能工作在**开漏 (Open-Drain)** 模式，平时高阻浮空，仅在按下时瞬间下拉接地。严禁误配置为推挽输出高电平向主板引脚倒灌电流。
   - **指示灯侦测引脚 (GPIO 7 / GPIO 8)** 必须并联在插有机箱前面板 LED 负载的插头上（利用 LED 自身 2V~3V 管压降），严禁在未接 LED 空载时直接接驳 5V/12V 电源轨，否则会直接过压击穿 ESP32 芯片。

4. **企业网络凭据泄露风险**
   - 本项目支持 802.1X 企业网络认证 (WPA2-Enterprise PEAP)。
   - 真实学号、统一认证密码、校园网凭据绝不可直接写入公开的 `.ino` 源码中。必须存放在被 `.gitignore` 排除的 `secrets.h` 本地文件中。

## 功能

| 能力 | 说明 |
|---|---|
| 短按电源键 | 开机 / 正常关机 |
| 长按 6 秒 | 硬断电（系统卡死时用） |
| 复位键 | 按一下 = 硬重启 |
| 开机状态回读 | 从**电源灯**或 **SATA +5V 主轨**分压进 GPIO → 知道电脑真实开/关（MQTT 里带 `pc` 字段） |
| 硬盘活动回读 | 硬盘灯分压进 GPIO → 活动次数、距上次活动秒数 |
| 机箱按键回读 | 电源键那根线本身可读，物理按一下也能上报（`btn_down`/`btn_up`） |
| 遥控通道 | MQTT（主）/ 蓝牙（改配置 + 本地控制）/ 串口 |
| 蓝牙改配置 | 手机 App（nRF Connect、LightBlue 等）写 JSON 改 WiFi/MQTT/引脚，**不用重烧** |

## 硬件接线

### 0. 前提

- **BIOS 里必须关闭 `ErP/EuP`**：否则关机后主板切断待机供电，ESP 直接断电、按键也不响应。
- ESP 必须**常带电**（主板内部 USB 2.0 九针插针取 5V/GND：红=+5V，黑=GND；或机箱后面标了充电图标的 USB 口）。

### 1. 电源键（一根线）

顺机箱前面板线束找到 `POWER SW` 两针插头，从**背面**把杜邦线铜芯贴着其中一根线捅进去（或剥线缠接），另一端接 **GPIO5**。

- ESP 与主板**共地**（靠供电那根 USB 线），所以只要这一根信号线。
- 引脚是**开漏**：平时高阻（等于没接），按下时拉低 500ms；**从不输出高电平**。
- 机箱原按键照常能用，两者并联互不影响。

### 2. 复位键（可选，一根线）

同上，找到 `RESET SW` 两针插头 → **GPIO6**。

### 3. 电源指示灯回读（开机状态侦测）

顺着机箱前面板线束找到印 `PLED+` / `POWER LED+` 的插头，从**插头背面**捅入一根杜邦线接 **GPIO7**。

- **电气标准**：高电平有效（Active High）。
- **判定逻辑**：电脑开机时主板向 LED 供电，由于机箱灯珠管压降，线路上电压稳定在 2.5V~3.3V 之间（安全电压区间），ESP 读到 **高电平 (1)**；电脑关机断电，读到 **低电平 (0)**。
- 零改动、零分压电阻，原机箱电源灯正常点亮。

### 4. 硬盘指示灯回读（磁盘读写活动侦测）

找到机箱前面板线束印 `HDLED-` / `HDD LED-` 的插头，从**插头背面**捅入一根杜邦线接 **GPIO8**。

- **电气标准**：低电平有效（Active Low）。
- **判定逻辑**：平时空闲为高电平；磁盘有读写活动瞬间，主板下拉接地导通回路点亮灯珠，ESP 捕捉到 **低电平/下降沿 (0)** 即判定为磁盘活动，用于 Web App 硬盘跳动灯高频闪烁。


## 编译烧录

1. Arduino IDE，开发板选 `ESP32S3 Dev Module`
2. 库管理器装 **PubSubClient**（BLE / WiFi / Preferences 都是核心自带）
3. 把 `secrets.example.h` 复制成 `secrets.h`，填 WiFi、MQTT、引脚、蓝牙口令
4. 烧录 → 开机即用，串口 115200 能看到 `[BOOT] ... / [WiFi] 连上了 / [MQTT] 已连接`

## 怎么用

### MQTT（主通道，人在外面也能用）

| 主题 | 方向 | 内容 |
|---|---|---|
| `<前缀>/set` | 下发 | `press`/`on`/`off`/任意 = 短按；`force` = 硬断电；`reset` = 复位；`status` = 立刻上报 |
| `<前缀>/state` | 上报 | 完整状态 JSON（retained，掉线由 broker 发遗嘱 `{"online":0}`） |
| `<前缀>/pc` | 上报 | 电脑状态 `1`/`0`/`-1`（-1 = 没接侦测） |
| `<前缀>/pc_txt` | 上报 | `开机` / `关机` / `未接`（中文，适合直接绑文本组件） |
| `<前缀>/act` | 上报 | 磁盘活动累计次数 |
| `<前缀>/actago` | 上报 | 距上次磁盘活动多少秒（65535 = 从未） |
| `<前缀>/btn` `/rst` | 上报 | 机箱电源键 / 复位键当前是否被按下（1/0） |
| `<前缀>/rssi` `/up` | 上报 | WiFi 信号 / 运行秒数 |

`<前缀>/state` 的完整 JSON：

```json
{"online":1,"wifi":1,"rssi":-45,"ip":"10.20.x.x","up":3600,
 "pc":1,"btn":0,"rst":0,"act":1234,"actago":3,
 "evt":"press","n":7,"cloud":1,"ble":0}
```

手机 App（如 `IoT MQTT Panel`）：加一个 **Button** 绑 `<前缀>/set` 发 `press`；
再加几个 **Indicator / Text** 分别绑 `<前缀>/pc_txt`、`<前缀>/actago`，就能看到"开机/关机""磁盘还忙不忙"。

> ⚠️ **主题前缀就是密码**：`broker.emqx.io` 是公共 broker，谁猜到前缀谁就能关你的机。

### 蓝牙（改配置 + 本地应急控制）

设备广播名 **`pc_pwrbtn`**，服务/特征 UUID：

| 特征 | 属性 | 用途 |
|---|---|---|
| `7a1e0002-9c3b-4f2a-8d5e-1b2c3d4e5f60` | 读 / 写 | **配置**：读出来是当前配置（故意不含密码）；写入 JSON 改参数 |
| `7a1e0003-9c3b-4f2a-8d5e-1b2c3d4e5f60` | 读 / 通知 | **状态**：和 MQTT 的状态 JSON 一样 |
| `7a1e0004-9c3b-4f2a-8d5e-1b2c3d4e5f60` | 写 | **命令**：`press` / `force` / `reset` / `status` |

用 nRF Connect / LightBlue：

1. 扫描 → 连 `pc_pwrbtn`
2. 写 `0002` 特征一段 JSON（**必须带 `pin`**，就是 `secrets.h` 里的 `DEF_BLE_PIN`）：

```json
{"pin":"123456","topic":"pcbtn/新后缀","mqttHost":"broker.emqx.io","mqttPort":8883,"mqttTls":1}
```

只写要改的字段即可，剩下的保持不变；写完设备 3 秒后自动重启生效。
加 `"reset":1` 表示清空所有蓝牙改过的参数、回到 `secrets.h` 的默认值。
想改哪个引脚（比如把复位键设成 6）：`{"pin":"123456","pinRst":6}`

3. 写 `0004` 特征 `press` 就能就地开/关机（蓝牙只在十几米内有效，所以命令不要口令）。

> 不想要蓝牙：把固件里 `BLE_ENABLE` 改成 0 重新烧录即可。

### 串口（115200）

| 输入 | 动作 |
|---|---|
| `p` | 短按电源键 |
| `f` | 长按 6 秒（硬断电） |
| `r` | 按一下复位键 |
| `s` | 打印状态 JSON |
| `d` | 清空蓝牙改过的参数，回到 `secrets.h` 默认值（3 秒后重启） |

## 常见问题

- **电脑关机后 ESP 也断电** → BIOS 里 `ErP/EuP` 没关，或 ESP 没接在待机供电口上。
- **MQTT 连不上** → 端口被网络封（校园网实测放行 8883/8084）、主题前缀不一致、或 broker 地址写错。
- **`pc` 读到 -1** → 没接侦测线，或者引脚号填了 0。
- **`pc` 读到反** → 蓝牙写 `{"pin":"...","vsenInv":1}`。
- **改了蓝牙参数想退回去** → 串口敲 `d`，或写 `{"pin":"...","reset":1}`。

## 安全提示

- 长按 6 秒 = **硬断电**，复位 = **硬重启**，别在机器干活时乱按。
- 主题前缀 = 密码；`secrets.h`（含 WiFi/MQTT 密码、蓝牙口令）已在 `.gitignore` 中，公开仓库前用 `git log -p -- secrets.h` 确认历史干净。
- 侦测脚**必须分压**再进 ESP。
